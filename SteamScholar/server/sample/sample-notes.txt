Chapter 1: Big-O Notation

Big-O notation describes how the running time or memory use of an algorithm grows as the input size n grows. It gives an upper bound on growth and ignores constant factors and lower-order terms, so an algorithm that takes 3n + 7 steps is simply O(n), and one that takes n^2 + 100n steps is O(n^2). Big-O is usually quoted for the worst case unless stated otherwise.

Common growth rates, from slowest-growing to fastest-growing:
- O(1), constant time: the work does not depend on n. Example: reading an array element by its index.
- O(log n), logarithmic time: the problem is cut by a constant fraction at each step. Example: binary search on a sorted array, which halves the search range each step.
- O(n), linear time: the work grows in proportion to n. Example: scanning every element of a list to find the maximum.
- O(n log n), linearithmic time: typical of efficient comparison sorts such as merge sort.
- O(n^2), quadratic time: often caused by two nested loops over the same input. Example: comparing every pair of elements.
- O(2^n), exponential time: the work doubles with each extra input element. Example: listing every subset of a set.

When an algorithm runs one step after another, the costs add and the larger term dominates: an O(n) loop followed by an O(n^2) loop is O(n^2) overall. When one loop is nested inside another, the costs multiply: a loop of n iterations containing a loop of n iterations is O(n^2).

Space complexity uses the same notation to describe extra memory. An algorithm that reverses an array in place uses O(1) extra space, while one that copies the array first uses O(n).

Chapter 2: Arrays and Dynamic Arrays

An array stores elements in one contiguous block of memory. Because every element has the same size, the address of element i can be computed directly as the start address plus i times the element size. This is why reading or writing any element by index takes O(1) time, a property called random access.

Contiguous storage has a cost. Inserting or deleting an element in the middle of an array requires shifting every later element by one position, which takes O(n) time in the worst case. A static array also has a fixed capacity chosen when it is created.

A dynamic array (such as a Python list, a Java ArrayList, or a C++ vector) removes the fixed-capacity limit. It keeps an underlying static array with some unused capacity. Appending to the end is O(1) while spare capacity remains. When the array is full, it allocates a new, larger array, typically double the old capacity, and copies every element over, which takes O(n) time for that one append.

Because the capacity doubles, these expensive copies happen rarely. Spread across a long sequence of appends, the total copying work is proportional to the number of appends, so appending has an amortized cost of O(1). Amortized analysis averages the cost of operations over a worst-case sequence; it does not mean every single append is fast.

Arrays also have good cache locality: neighboring elements sit next to each other in memory, so iterating through an array is fast on real hardware.

Chapter 3: Linked Lists

A linked list stores each element in a separate node. In a singly linked list, each node holds a value and a pointer to the next node; the list keeps a pointer to the first node, called the head, and the last node points to null. In a doubly linked list, each node also holds a pointer to the previous node, which allows traversal in both directions at the cost of extra memory per node.

Nodes can live anywhere in memory, so there is no random access. Finding the element at position i requires starting at the head and following i pointers, which takes O(n) time.

The strength of a linked list is cheap insertion and deletion once you already have a reference to the right node. Inserting a new node at the head is O(1): point the new node at the old head and update the head pointer. Inserting after a known node is also O(1), because only a couple of pointers change and no elements are shifted. Deleting a node from a doubly linked list is O(1) given a reference to that node. In a singly linked list, deleting a node requires a reference to the node before it, since that predecessor's pointer must be updated.

If a singly linked list keeps a tail pointer, appending at the end is O(1). Without a tail pointer, appending requires walking the whole list, which is O(n).

Compared with arrays, linked lists use extra memory for pointers and have poor cache locality, so traversal is usually slower in practice even though both are O(n).

Chapter 4: Stacks and Queues

A stack is a collection that follows Last-In, First-Out (LIFO) order: the most recently added element is the first one removed. Its core operations are push (add to the top), pop (remove from the top), and peek (look at the top without removing it). All three are O(1) when the stack is implemented with a dynamic array (using the end of the array as the top) or with a linked list (using the head as the top).

Stacks appear wherever work must be undone or resumed in reverse order. The function call stack stores each active function call; a call pushes a frame and a return pops it. Other uses include undo features in editors, checking that brackets are balanced, and depth-first search.

A queue follows First-In, First-Out (FIFO) order: elements leave in the same order they arrived, like a line at a ticket window. Its core operations are enqueue (add at the back) and dequeue (remove from the front). A linked list with head and tail pointers supports both in O(1) time.

Implementing a queue with a plain array by removing from index 0 is a poor choice, because every dequeue would shift all remaining elements, costing O(n). A circular buffer solves this: it keeps front and back indices that wrap around to the start of a fixed array, giving O(1) enqueue and dequeue.

Queues are used in breadth-first search, print and task scheduling, and buffering data between producers and consumers. A deque (double-ended queue) allows insertion and removal at both ends.

Chapter 5: Hash Tables

A hash table stores key-value pairs and supports insert, lookup, and delete in O(1) time on average. It uses a hash function to convert each key into an index in an underlying array of buckets. A good hash function is deterministic (the same key always produces the same index) and spreads keys evenly across the buckets.

A collision happens when two different keys hash to the same index. Collisions are unavoidable, so every hash table needs a strategy for them:
- Separate chaining: each bucket holds a list of all entries that hashed to it. Lookup hashes the key, then searches that bucket's list.
- Open addressing: all entries live in the array itself. On a collision, the table probes other slots in a fixed sequence (for example, linear probing checks the next slot, then the next) until it finds an empty one.

The load factor is the number of stored entries divided by the number of buckets. As the load factor rises, collisions become more frequent and operations slow down. To keep operations fast, a hash table resizes when the load factor passes a threshold (0.75 is a common choice): it allocates a larger bucket array and rehashes every entry into it. Like dynamic array growth, resizing is O(n) when it happens but amortized O(1) per insertion.

In the worst case, if many keys collide into the same bucket, operations degrade to O(n). Hash tables also do not keep keys in sorted order, so finding the smallest key or listing keys in order requires extra work.

Chapter 6: Binary Search Trees

A binary tree is made of nodes, each with at most two children, called the left child and the right child. The topmost node is the root, and nodes with no children are leaves. The height of a tree is the number of edges on the longest path from the root down to a leaf.

A binary search tree (BST) adds an ordering rule: for every node, all keys in its left subtree are smaller than the node's key, and all keys in its right subtree are larger. This rule must hold for entire subtrees, not just for a node's immediate children.

To search for a key, start at the root and compare: if the key is smaller, go left; if larger, go right; repeat until the key is found or a null child is reached. Insertion follows the same path and attaches the new node where the search ended. Search, insert, and delete all take O(h) time, where h is the height of the tree.

A balanced BST with n nodes has height about log n, so its operations run in O(log n) time. If keys are inserted in sorted order into a plain BST, every new node becomes a right child, the tree degenerates into a structure shaped like a linked list, and operations slow to O(n). Self-balancing trees such as AVL trees and red-black trees perform rotations during insertion and deletion to keep the height O(log n).

An in-order traversal visits the left subtree, then the node, then the right subtree. On a BST, an in-order traversal visits the keys in sorted ascending order, which is a key advantage of BSTs over hash tables.
